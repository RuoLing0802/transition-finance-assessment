## 一、你的角色与本轮任务

你是本项目的`02_软件开发`。本轮实施：

> **M5：带来源、版本、证据位置、准入状态和运行隔离的可追溯知识检索层。**

M5要让当前专业Agent工作台具备以下真实闭环：

```text
受控知识资产
→ 记录级准入审查
→ 文档解析与确定性切片
→ 本地索引
→ 结合当前企业行业的受控检索
→ 返回候选证据及精确引用
→ Agent解释或离线直接展示
→ 记录当前assessment_run的检索日志
```

M5不是碳核算、行业对标、转型评分或授信模型。检索结果只是候选证据，不得自动改变企业事实、执行规则、因子、权重、阈值或授信结论。

- 查询扩展；
- 重排；
- 缓存；
- Agent提示上下文；
- 检索金标准；
- 特征或标签；
- 评估报告的事实生成链路。

### 4.3 大模型、LangGraph与LangChain边界

- LangGraph只负责工作流状态、节点路由、暂停/恢复和人工确认；
- LangChain Core只负责受控工具、消息和Runnable包装；
- 知识来源、切片、索引、准入规则、过滤、引用和日志由独立业务模块负责；
- 大模型可以提出检索词和解释检索结果，但不能决定来源是否准入、不能改写引用、不能把候选证据升级为正式规则；
- Agent不可自行访问原始PDF目录或绕过检索服务读取被阻断来源。

### 4.4 国家温室气体排放因子库边界

M5只保存和检索国家因子库的：

- 来源名称；
- 发布机构；
- 版本/发布日期；
- 适用对象和情景说明；
- 官方URL；
- 页面或文件定位；
- 更新机制和人工复核状态。

M5不得导入或自动调用具体因子值，不得调用网站计算器形成项目碳结果。全国碳市场情景与其他情景的具体因子治理、快照、单位、地区、年份和计算接口留待M6。

## 六、M5-v1记录级白名单和四级可见性

M5必须建立显式、可版本化的准入清单，例如`M5-ALLOWLIST-v1`。不得只凭文件存在、文件名、关键词或开发者主观判断入库。

### 6.1 四级可见性

| 级别 | 含义 | 普通Agent可检索 | 可作为确定性规则 |
|---|---|---:|---:|
| `searchable_candidate` | 来源、版本、原件/URL和定位达到M5候选检索门槛 | 是，但必须显示候选/核验状态 | 否 |
| `metadata_only` | 只能安全登记来源和适用性元数据 | 只返回元数据，不返回正文条款 | 否 |
| `diagnostic_only` | 用于治理、缺口提示和负向测试 | 否；仅管理员/测试显式查询 | 否 |
| `blocked` | 来源、全文、定位或完整性不满足门槛 | 否 | 否 |

任何状态变化都必须形成新的准入清单版本和索引版本，不能原地覆盖历史状态。

### 6.2 白名单生成优先级、连接键与严格裁决

`M5-ALLOWLIST-v1`必须由程序生成并输出逐记录清单，不允许开发者手工在代码中散落判断。来源冲突按以下顺序裁决：

1. D-027和本文件的强制阻断边界；
2. 19号接收审查的正式采纳/阻断结论；
3. 20号接收台账的文件有效性、SHA-256、文本状态和条款核验；
4. 08号来源台账的来源身份、准入状态和使用边界；
5. 14号文献表的全文和用途状态；
6. 12号候选治理清单；
7. 13号测试设计。

同一记录状态不一致时采用最严格状态：`blocked > metadata_only > diagnostic_only > searchable_candidate`。不得用低层文件的“候选”覆盖高层审查的“阻断”。

连接键依次为：

1. `canonical_source_id/source_id/linked_source_id`精确一致；
2. `document_hash/SHA-256`精确一致；
3. 已由14条铜条款表同时绑定的`source_id + 文件SHA-256`；
4. 其他仅标题相似、文件名相似或人工猜测的映射一律不自动合并，转入`metadata_only`并记录`mapping_required=true`。

每条白名单结果至少输出：`allowlist_entry_id`、`source_id`、`asset_id`、`document_id`、`visibility`、`decision_basis`、`decision_source_file`、`decision_source_row`、`mapping_method`、`decided_at`和`allowlist_version`。

初始来源ID冻结如下：

- `searchable_candidate`候选正文来源：`CETS-VG-001`、`POL-001`、`STD-001`、`STD-002`、`STD-003`、`STD-004`、`STD-005`、`STD-007`、`STD-008`、`STD-009`、`STD-010`、`MEE-GHG-QA-2025`；仍须逐文件通过哈希、可读性、定位和泄漏检查，否则自动降级；
- `metadata_only`：`CETS-004`、`CETS-POWER-UP-2026`、`CETS-VG-002`、`CETS-VG-003`、`FAC-DB2`；
- 12篇`CN-LIT-*`：只允许治理确认的元数据、摘要/结论片段进入`searchable_candidate`研究证据层；
- 其他未形成无歧义来源映射的补充PDF：只登记资产或进入`metadata_only`，不得自动加入正文索引。

### 6.3 初始`searchable_candidate`

初始正文检索仅允许纳入满足下列全部条件的记录：

1. 08号台账`source_identity_status=已核验`；
2. 有官方URL或受控原件及SHA-256；
3. 08号`admission_status`明确写明可用于M5候选知识、口径解释或候选能效证据；
4. 本地文件可读取；
5. 切片能够绑定页码、表号、章节、网页锚点或其他可复核定位；
6. 未命中任何泄漏或阻断规则。

当前优先纳入的类型为：

- 14条已核验铜行业候选条款；
- 08号台账中满足上述条件、且正文可读的M5候选来源；
- 12篇中文文献的元数据及已经治理的摘要/结论片段；
- 已核验官方网页的解释性内容。

正文检索结果必须标明`source_role`、`verification_status`和`use_boundary`。14条铜行业条款可显示数值和单位，但不能被程序当作自动阈值、评分参数或授信依据。

### 6.4 初始`metadata_only`

以下对象只登记来源元数据：

- 0页无效的发电设施指南记录；
- 低文本、尚未OCR或未完成条款定位的政策/标准；
- 国家温室气体排放因子库及其政策、标准、计算器入口；
- 只有官方页面、尚无可复核正文切片的记录；
- 尚未建立无歧义`canonical_source_id`映射的有效PDF。

元数据结果必须明确显示“正文不可用/待OCR/待定位/不得引用条款”，不得生成看似来自原文的摘要。

### 6.5 初始`diagnostic_only`

- 12号工作簿的731条候选治理记录；
- 11条`GOV-IND-*`治理记录；
- 历史CETS ID迁移说明；
- 被阻断来源的状态和补全要求；
- 13号负向测试需要的治理对象。

这一级只用于缺口提示、管理员诊断和自动测试。普通Agent工具不得返回其文本作为政策证据。

诊断记录只写入结构化`knowledge_governance_records`表，不写入FTS5或任何嵌入索引。13号测试通过内部测试仓储按稳定ID读取诊断记录；普通检索API和`search_knowledge`工具没有`include_diagnostic`参数。管理员诊断接口只能按ID或状态过滤读取，不做正文相关性搜索。

### 6.6 初始`blocked`

- 21条仍缺正式URL或受控原件的`F-SRC-*`来源；
- 1份0页无效PDF的正文；
- 15份低文本PDF中尚未完成OCR和定位的正文；
- 7篇尚未取得全文的英文文献正文；
- 未审查的具体排放因子值；
- `转型规划结论`及其派生文本；
- 任何个人绝对路径、搜索摘要或二手转载替代原文的内容。

## 七、推荐技术架构

### 7.1 总体原则

采用：

> **本地优先、模块化单体、确定性检索基线、可插拔语义增强、证据优先。**

M5核心不直接引入RAGFlow，也不要求Qdrant、LlamaIndex或外部向量服务。M3中提到的`KnowledgeRetriever`和LlamaIndex/Qdrant只是历史预留方向，不是当前强制技术选型。

### 7.2 M5-A必须实现

- 01在当前项目解释器中只读验证SQLite 3.51.0可创建FTS5虚拟表；02仍须在Web、macOS和未来Windows运行环境分别做能力检查；
- 元数据与审计状态：继续使用现有SQLite；
- 全文检索：优先使用SQLite FTS5；
- 中文检索：在写入FTS5前生成确定性的规范化词、标准号、行业词和中文二/三元字符token；
- FTS5不可用时：回退为本地确定性标题/标准号/关键词/片段匹配，不得依赖外部服务；
- 检索排序：字段权重、行业过滤、来源角色、核验状态、版本有效性和去重；
- 引用：每条结果必须返回来源、版本、定位、状态和边界；
- Agent集成：以只读工具接入现有编排；
- UI：在右侧检查器增加紧凑的“知识依据”面板。

### 7.3 M5-B可选增强

只有M5-A全部通过后，才可增加可插拔`EmbeddingProvider`和`Reranker`接口。可选增强必须满足：

- 不改变SQLite元数据和准入状态的真实来源；
- 无外部API、无向量服务时仍可完成全部核心流程；
- 嵌入输入同样执行白名单和泄漏过滤；
- 向量索引按知识版本隔离并可重建；
- 不把模型相似度写成政策权威性或评分结论；
- 不因增加语义检索而直接部署RAGFlow。

本轮验收不得依赖M5-B完成。

## 十、导入、切片与索引规则

### 10.1 导入必须先dry-run

每次构建索引前先输出：

- 发现来源数；
- `searchable_candidate`数；
- `metadata_only`数；
- `diagnostic_only`数；
- `blocked`数；
- 重复哈希；
- 无法解析文件；
- 缺来源ID、版本、URL、哈希或定位的记录；
- `转型规划结论`和派生文本泄漏命中；
- 将被实际写入的来源、文档和切片数量。

dry-run失败或泄漏命中大于0时必须阻断构建。

### 10.2 原件只读和去重

- 不修改、重命名或覆盖原始PDF/Excel；
- 以SHA-256识别同一原件，重复副本只登记别名；
- 同一来源不同版本分别保存，不覆盖旧版本；
- 原件不复制到公开代码目录；
- 索引和数据库写入用户应用数据目录，不写安装目录。

### 10.3 确定性切片

- 政策/标准优先按章节、条款、表格和页码切分；
- 表格保留表号、表题、单位和页码，避免跨表拼接；
- 普通正文可采用约800—1200个中文字符的上限和小范围重叠；
- 文献仅导入治理确认的摘要、结论或指定片段，不默认把整篇全文作为普通Agent语料；
- 低文本PDF在OCR或人工定位前只登记元数据；
- `chunk_id`由来源ID、文档哈希、定位和正文哈希确定，重复构建保持稳定；
- 切片正文不得包含个人绝对路径或参考结论字段。

### 10.4 版本与撤回

- 索引版本不可原地篡改；
- 来源撤回、失效或状态降级后，重建新版本并保留审计记录；
- 默认检索当前有效版本；历史版本只能由管理员显式查看；
- 新版本不得删除旧日志引用的`source_id`、`document_id`和`chunk_id`解释能力。
- “默认当前有效版本”只适用于某个`assessment_run`的首次检索；冻结后必须持续使用`assessment_run_knowledge_context.index_version_id`。
- 历史回放从`knowledge_index_members`和运行级知识上下文读取准入、来源元数据、排序、token和行业映射快照，不读当天可变配置。

### 10.5 `knowledge_as_of`时间口径

- 每个`assessment_run`首次知识检索时冻结`knowledge_as_of`；默认取该运行`created_at`对应的日期；
- 用户或管理员可在创建运行时显式指定合法的`knowledge_as_of`，后续同一运行不得静默变化；
- 来源有效性按`effective_at <= knowledge_as_of`且`expires_at`为空或晚于该日期判断；
- 只有年份、没有具体生效日的来源标记`date_uncertain=true`，不得静默推断为1月1日；
- 企业2024—2025报告期不自动替代政策有效日期，除非运行显式采用该历史评估日期；
- 检索日志和结果必须返回`knowledge_as_of`，确保历史回放不随系统当天日期变化。

## 十一、检索与排序流程

推荐流程：

```text
接收query
→ 后端校验assessment_run
→ 读取当前enterprise_id和行业
→ 应用来源准入与可见性过滤
→ 标准号/标题/行业词规范化
→ FTS5词法召回
→ 可选语义召回
→ 字段权重与行业过滤
→ 版本有效性和来源角色过滤
→ 去重与结果组装
→ 返回证据卡和引用
→ 写入运行级检索日志
```

排序必须遵循：

1. 精确标准号、来源ID和文号优先；
2. 当前行业及适用对象匹配优先；
3. 正式发布方和来源身份已核验优先；
4. 精确页码/条款/表号定位优先；
5. 当前有效版本优先于已被替代版本；
6. 研究文献不得排在适用的正式政策/标准之前冒充规范依据；
7. `metadata_only`不得返回伪正文；
8. 无足够证据时返回“未找到可用证据”，不得让模型补写。

禁止只依赖大模型给出的相关性分数决定准入或权威性。

### 11.1 M5-A稳定排序配置

M5-A必须冻结并版本化`ranking-config-v1`：

1. 先完成行业、来源角色、可见性、`knowledge_as_of`和版本有效性过滤；
2. `tier=0`：`source_id`、标准号或文号精确匹配；
3. `tier=1`：规范化标题完整匹配；
4. `tier=2`：FTS5匹配，列权重固定为标准号12、标题10、章节/表题6、正文1；
5. `tier=3`：仅在FTS5不可用时使用确定性降级匹配；
6. 每个匹配tier内的来源角色优先级冻结为：`official_standard`、`official_policy`、`regulatory_guidance`、`official_methodology`、`research_literature`、`other`；未知角色按`other`处理并告警；
7. 同tier且同来源角色内，`chunk`先于`source_metadata`；`chunk`依次按FTS5 BM25分数升序、核验状态优先级、`source_id`升序、`chunk_id`升序打破并列；`source_metadata`仅参与tier 0/1的精确ID/文号/标题匹配，依次按核验状态、`source_id`和`document_id`升序（空值排后）打破并列；
8. `top_k`默认5，合法范围1—10，排序完成后再截断；
9. M5-A不使用大模型查询扩展；查询规范化采用`zh-ngram-v1`：Unicode规范化、标准号/英文大小写统一、上述行业映射及项目行业同义词表、中文二元与三元字符token，去重后按字典序稳定输出；
10. 排序配置、行业映射/同义词表或token算法改变时，必须生成新`ranking_config_hash`和新索引版本。

FTS5与降级实现可以使用不同内部得分，但必须遵守上述tier和最终并列顺序。同一索引版本、`knowledge_as_of`、查询和过滤条件必须返回同序结果。

## 十三、运行隔离与安全边界

### 13.1 全局知识与运行上下文分离

- 政策、标准和文献知识库可作为全局只读资产复用；
- 企业事实、企业附件、用户查询、检索日志、结果引用和会话解释必须绑定当前`assessment_run_id`；
- M5不把企业附件并入全局政策知识索引；
- 当前企业附件继续由已有证据模块处理；如需要未来检索，必须使用独立的运行级索引，不属于本轮默认范围。

### 13.2 跨运行检查

- 运行A不得读取运行B的查询、结果、附件或企业事实；
- 企业A的行业过滤不得被企业B复用；
- 切换运行后前端必须清空旧运行的知识结果并重新请求；
- 只读全局知识块可复用，但每次返回都记录当前运行和知识版本；
- 所有ID校验在后端执行。

### 13.3 内容安全

- 知识正文中的指令性文字只按数据处理，不作为系统提示执行；
- 模型不可通过提示注入请求管理员索引、被阻断来源或其他企业数据；
- 官方URL只作为证据链接，不允许前端自动执行下载或脚本；
- API错误不得泄露本机绝对路径、堆栈、密钥或原始数据库位置。

## 十五、离线回退

M5必须在无外部大模型、无嵌入服务、无网络时完成：

1. 载入既有本地知识索引；
2. 按标准号、标题、行业和关键词搜索；
3. 返回候选证据卡、引用和边界；
4. 显示元数据级来源；
5. 记录检索日志；
6. 给出固定模板式“找到证据/证据不足”摘要。

如果FTS5不可用，系统应进入明确的本地降级模式并使用确定性匹配；不得把空结果伪装为成功，也不得静默调用外部服务。

- 731条12号候选记录不进入普通索引；
- 21条`F-SRC-*`来源保持阻断；
- 15份低文本正文不进入普通正文索引；
- 0页PDF正文阻断；
- 重复PDF按SHA-256去重；
- 同名不同哈希不得误判为同一版本；
- 来源状态降级后生成新索引版本。

### 17.2 泄漏测试

至少扫描：

- 工作表名；
- 字段名；
- 参考结论文本；
- 派生摘要；
- 查询扩展；
- 全文索引；
- 可选嵌入输入；
- 缓存；
- Agent工具输出；
- 检索日志；
- 13号金标准。

`转型规划结论`及其派生内容命中必须为0。任何命中都阻断索引构建。

### 17.3 检索与引用测试

- 标准号精确检索；
- 中文标题、行业、设备和转型路径关键词检索；
- 11行业逐行业路由；
- 跨行业禁止命中；
- 条款、表号、页码和官方URL可回溯；
- 版本替代和失效过滤；
- 文献与政策来源角色不混用；
- 元数据来源不生成伪正文；
- 无结果时返回证据不足；
- 同一索引、同一查询、同一过滤条件返回稳定结果。
- 稳定性测试同时固定`knowledge_as_of`和`ranking_config_hash`；

### 17.4 13号44条测试

- 44条全部执行并形成逐条结果；
- 33条行业测试按表内`expected_behavior`判断，不得把“无权威结果”误判为失败；
- 11条负向测试必须全部通过；
- `GOV-IND-*`只可作为治理诊断，不得成为政策证据；
- 记录Top-K、目标来源/切片、实际来源/切片、是否命中、降级状态和原因；
- 检索相关性只能作为内部测试结果报告，不得写成比赛正式准确率或真实业务效果。

### 17.5 隔离与安全测试

- 企业A不能读取企业B的查询、附件、结果或企业事实；
- 运行A不能读取运行B的检索日志；
- 跨thread请求被拒绝；
- 切换运行后前端不残留旧证据；
- 提示注入不能绕过白名单；
- 前端响应和错误中无API Key、绝对路径或数据库位置。

### 17.6 回归与工程测试

- Python全量测试不回退；
- M4暂停/恢复、人工确认、乐观锁和离线回退不回退；
- 前端单元/组件测试通过；
- TypeScript类型检查通过；
- 前端生产构建通过；
- Playwright覆盖一次完整知识检索流程；
- `pip check`通过；
- `git diff --check`通过；
- 敏感信息和原始资料扫描通过。

## 十八、M5验收标准

M5只有同时满足以下条件，才可交01审查：

1. 本地知识索引可以从受控白名单重复构建；
2. 每个普通检索结果都能追溯到来源、版本、文档哈希和证据位置；
3. 731条候选治理记录未被整表导入普通索引；
4. 被阻断、低文本、无效和缺全文记录不会生成伪正文；
5. 14条铜候选条款按候选证据返回，不被执行为阈值或评分；
6. 12篇中文文献按研究证据返回，不冒充政策或标准；
7. 国家因子库只返回来源和适用性元数据，具体因子自动调用为0；
8. `转型规划结论`及派生内容在索引、检索、模型上下文和测试中命中为0；
9. 全局知识可复用，但查询、日志和结果严格绑定当前评估运行；
10. 无外部模型、网络或向量服务时仍可检索和展示引用；
11. 13号44条测试有逐条真实执行记录，11条负向测试全部通过；
12. M1—M4现有功能和测试不回退；
13. UI保持M3三栏结构，知识依据主要进入右侧检查器；
14. 未实现M6—M8、Windows或报告扩展；
15. 没有原始PDF、Excel、数据库、索引、缓存或密钥进入待提交清单。

上述验收只能证明11行业使用同一检索契约、路由、证据不足处理和负向门槛，不证明11行业已经具有等量知识、同等成熟度或完整规则覆盖。行业材料不足必须在结果和测试报告中如实显示。
