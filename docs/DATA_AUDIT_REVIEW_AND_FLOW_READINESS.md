# 配套数据审计复核与流程软件准备清单

**版本**：v0.1
**日期**：2026-08-15
**维护对话**：`01_项目总控与决策`
**适用数据**：命题方配套脱敏、模拟生成的比赛开发测试工作簿
**当前状态**：审计结果已归档；数据问题待完善；流程软件尚未授权开发

## 1. 文件用途

本文件集中保存两部分内容：

1. `03_数据、政策与评分体系`提交的配套数据初步审计结论；
2. `01_项目总控与决策`对审计结论的采纳分类、问题清单、注意事项和流程软件准备要求。

它是后续完善数据问题、确认数据契约和准备端到端流程验收的工作入口，不是程序代码、数据库迁移脚本或评分规则手册。详细事实画像见 [`DATA_PROFILE.md`](DATA_PROFILE.md)，候选数据契约见 [`DATA_CONTRACT.md`](DATA_CONTRACT.md)。

## 2. 证据与数据边界

- 本轮03成果以若翎在`01_项目总控与决策`中提供的完整审计文字为依据；仓库中未发现独立的03审计报告、数据画像或计算输出文件。
- 原始工作簿、外层ZIP和数据目录仍保存在本地受控环境，不进入公开GitHub。工作簿SHA-256、ZIP SHA-256、文件大小和接收信息见 [`DATA_STATUS.md`](DATA_STATUS.md)。
- 配套工作簿是脱敏、模拟生成的比赛开发测试数据，不是真实企业业务数据，不能用于真实企业融资、真实碳核算、授信结论、模型效果或用户效果宣称。
- 03初步审计已完成结构和基础质量画像，但独立数据字典、正式评分标签、训练/测试划分、权威行业规则、排放因子和折标系数仍未取得。

## 3. 03审计结论摘要

### 3.1 工作表和数据角色

| 数据角色 | 工作表 | 后续流程边界 |
|---|---|---|
| 主要程序输入 | `基本信息`、`能耗信息`、`补充信息` | 进入标准化、质量检查、行业路由和经授权后的评估输入层 |
| 规则与知识 | `转型目录` | 进入规则/知识层；补充来源、版本、生效日期和适用范围；不作为普通模型特征 |
| 参考答案/验证对照 | `转型规划结论` | 独立保存，用于回放、参考答案、人工审阅和验证对照 |

`转型规划结论`除企业代号外的字段不得进入同一模型的训练特征、推理特征或标签生成链路。特别禁止回灌“建议改进方向”“匹配的转型路径名称”“近/中/长期行动建议”“规划书要点”等字段。

### 3.2 结构和关联

- `基本信息`：6个字段、1000行；`能耗信息`：22个字段、1000行；`补充信息`：10个字段、1000行；`转型规划结论`：9个字段、1000行；`转型目录`：4个字段、656行。
- 四张企业表的`企业代号`均为`TF0001`—`TF1000`，03报告称四表行数、集合和顺序一一对应，无空键、重复键或孤儿键。
- `细分行业/领域`和`主要产品/服务`不能互相覆盖；两者逐行完全相同仅240/1000。
- `转型目录`没有显式稳定ID；“行业+类别/领域+转型路径”在初步检查中唯一，但路径编号在同一行业复用，不能只使用编号。

### 3.3 缺失、范围和重复

03报告称能源及产量字段主要为2024/2025成对缺失：电力192、煤炭548、天然气318、热力556、柴油725、汽油950、水215、主要产品产量699；营业收入无缺失。产量和产量单位缺失699行完全一致。

其他初步结果：

- `补充信息`和`转型规划结论`无缺失；布尔字段仅有“是/否”；绿电比例在0—1之间；消费量、产量、营业收入未发现负数或零值。
- 成立年份为2001—2022；设备年限报告为4—26年；561家企业的设备年限超过“2025年减成立年份”，先作为警告候选。
- IQR高值可能反映行业和企业规模差异，不得未经确认直接删除。
- 主要用能来源文本项数量与主用能项数量一致，但144家企业的数值能源项多于文本列出的主要来源；该字段不是完整能源清单，数量不一致暂作软校验候选。

### 3.4 单位、语义和规则目录

- 初步观察单位：电力—万千瓦时；煤炭、柴油、汽油—吨；天然气—万立方米；热力—吉焦；水—万吨；营业收入—万元。
- 观察到的产量单位包括万吨、万吨公里、万平方米、万米、吨和亿千瓦时；行业对应关系仍需正式数据字典确认。
- 工作簿未明确组织边界、核算边界、Scope 1/2、温室气体种类、排放因子ID/版本、能源折标系数、设备年限截至日期、币种和期间定义。因此不能仅凭该工作簿完成正式碳排放核算。
- 目录覆盖缺口包括：钢铁49条、煤电8条、纺织93条的类别/领域为空；农业缺少“设施农业”；石化缺少“煤制烯烃”；水上运输存在“港口码头”与目录细分分类不一致。
- “匹配的转型路径名称”是多路径和解释文本拼接字段；初步解析的1980个引用均找到同业目录候选，但部分编号存在同业歧义。

## 4. 总控审查分类

### A. 建议采纳并已写入正式项目

- 三张输入表、一个规则目录表、一个参考结论表的角色分层。
- 四表企业代号闭合、字段数量、样本规模、初步字段类型和主要缺失/重复事实。
- 观察到的单位、跨表关联、目录路径编号复用、目录覆盖缺口和参考结论派生风险。
- 参考结论隔离和目标泄漏防护要求。
- 流程软件必须保留原始值、质量问题、处理状态和审计证据，不得静默补零、删除异常或覆盖原始输入。

### B. 合理但标记待确认

- 设备年限超存续期先警告；能源数量不一致先软校验；异常值按行业—规模分层复核。
- 产量单位—行业映射、目录覆盖缺口补充方式、路径文本解析和人工复核流程。
- 数据由宽表接收、按企业/年份/资源类型/指标类型形成长表逻辑视图。

### C. 专业判断，暂不作为确定方案

- 缺失状态枚举和各质量问题的阻断等级。
- 负值、比例越界、非法布尔值、年度错位、产量/单位单边缺失的最终处置。
- IQR异常值处理、设备年限告警口径、目录行级`rule_id`生成与版本策略。
- 候选逻辑数据表、数据库类型、模型特征工程和评分校准方法。
- 评分权重、阈值、模型选择、第二深验行业和MVP范围。

### D. 与现行项目决策的冲突

未发现直接冲突。03提出的“可作为第一版软件联调输入”必须服从精确开发口令“开始开发MVP”，不能解释为当前已授权编程。

## 5. 数据问题完善顺序

### P0：流程跑通前必须确认

1. 固定输入/规则/参考结论三层边界，建立特征视图禁止引用`转型规划结论`的检查项。
2. 固定`企业代号`跨表闭合检查、重复/空/孤儿键检查和批次文件哈希登记。
3. 明确原始值保留、缺失不补零、质量问题留痕和模拟数据标识。
4. 补齐最小数据字典：字段名、类型、单位、年份、空值含义、来源和可用范围。
5. 明确规则目录的临时行级标识和路径歧义的人工复核入口。

### P1：进入评估闭环前完善

1. 确认组织边界、核算边界、Scope 1/2、排放因子和折标系数来源。
2. 确认能源活动、产量和营业收入的期间、币种和单位口径。
3. 确认缺失状态、年度配对、能源软校验、设备年限告警和异常值分层规则。
4. 补充目录来源、版本、生效期、适用地区和行业覆盖映射。

### P2：正式评分和效果验证前完善

1. 取得正式评分标签、标注指南、金标准和训练/验证/测试划分。
2. 通过独立标签和专家复核确认评分权重、阈值、模型和第二深验行业。
3. 形成可复现的规则回放、参考答案对照、模型效果和性能测试报告。

## 6. “先跑通流程”软件的目标验收

以下是流程准备目标，不是当前开发授权：

1. **登记**：输入工作簿批次、来源、文件大小、SHA-256和模拟数据标识。
2. **读取**：读取三张主要输入表；把`转型目录`加载为规则/知识来源；单独加载`转型规划结论`为参考对照。
3. **关联**：以`企业代号`完成四张企业表关联，并输出重复、空键、孤儿键和行数不一致问题。
4. **质检**：展示缺失、单位、类型、范围、年度配对、能源数量和设备年限问题；所有问题可定位到企业和字段。
5. **隔离**：生成输入特征视图时，自动阻断`转型规划结论`字段和结论类字段回灌。
6. **规则匹配**：用行业、细分领域和目录行级标识产生候选路径；路径编号歧义进入人工复核，不静默选定。
7. **输出**：生成一份标明“模拟数据、不代表真实企业业务”的流程审计结果，包含数据质量问题、参考结论对照和待补材料。

流程软件的最低验收不是“得出一个评分”，而是“输入可登记、表可关联、问题可解释、参考结论隔离、规则可追溯、输出可复核”。评分权重、阈值和模型效果不属于本阶段验收。

## 7. 开发阶段边界

- 当前仍处于材料审阅与总体规划阶段；本文件不授权写程序、安装依赖、创建数据库或启动软件开发。
- 只有收到完全一致的口令“开始开发MVP”后，才能依据本文件和已确认的数据契约进入软件实现。
- 即使收到开发口令，也不得擅自把候选契约、暂定质量规则、模拟数据结果、参考结论或目标指标写成正式业务效果。
- 完整“8行业框架＋2行业深验”范围不因先做流程闭环而削减；铜产业仍是第一深验行业，第二深验行业待确认。
