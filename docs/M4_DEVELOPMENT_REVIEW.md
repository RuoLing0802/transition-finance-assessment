## 1. 审查范围与阶段结论

M3 React专业Agent工作台已在此前提交`562eba7`进入`main`。M4严格位于M3之后，目标是增加可恢复、可暂停、可人工确认的运行级工作流，不进入M5知识检索、M6碳核算、M7行业对标/转型行为、M8评分与信贷支持，也不处理Windows或报告扩展。

01经过初审、整改复审和简短终审，正式采纳以下M4能力：

- `baseline_review`与`evidence_followup`两类确定性工作流；
- LangGraph节点图、条件路由和进程内运行时检查点；
- LangChain Core `RunnableLambda`确定性节点包装；
- SQLite持久检查点、运行级线程绑定和严格乐观锁；
- 暂停、恢复、显式“暂不补充”、人工通过和退回；
- 跨运行隔离、新进程恢复和无LangGraph环境的离线回退；
- React工作流状态卡片、阶段按钮和运行状态展示。

## 2. 框架和业务边界

### 2.1 LangGraph

LangGraph只负责：

- 节点图；
- 条件路由；
- 以`assessment_run_id`派生的`thread_id`；
- 进程内运行状态衔接。

SQLite中的`workflow_checkpoints`才是持久化状态真实来源。LangGraph不保存或决定企业事实、数据质量规则、行业规则、碳核算、评分、证据库或授信结论。

### 2.2 LangChain Core

LangChain Core只通过`RunnableLambda`包装确定性节点。M4没有新增外部大模型推理逻辑，也没有让LangChain接管事实、规则、评分或证据。

### 2.3 数据与参考结论

工作流使用专用白名单分析视图，只包含三张输入表形成的`input_data`、质量问题、能耗趋势和目录候选。完整企业详情和独立参考对照仍由原接口处理。

`reference_comparison`与`转型规划结论`不得进入：

- 工作流输入和持久化状态；
- 外部模型输入；
- 知识检索输入；
- 训练或推理特征；
- 标签生成链路。

## 3. 运行隔离与检查点

每条检查点记录包含：

- `workspace_id`；
- `assessment_run_id`；
- `enterprise_id`；
- `workflow_name`；
- 由评估运行和工作流名称派生的`thread_id`；
- 状态、当前节点、版本、安全状态和检查点摘要。

同一评估运行和工作流只能有一个检查点，`thread_id`全局唯一。检查点更新使用严格版本递增和条件更新；陈旧版本返回冲突，不能以相同版本后写覆盖前写。

## 4. 整改闭环

初审发现的问题均已整改：

1. 人工确认只允许从`waiting_human_review`进入，越级操作返回409；
2. `waiting_for_input`禁止空回答；用户必须提交真实回答或显式确认暂不补充；
3. 暂停保存`paused_from_status`，不能通过“待补充→暂停→空恢复”绕过校验；
4. 重复暂停返回冲突；
5. 检查点采用严格乐观锁；
6. 工作流输入改为白名单视图，排除参考结论；
7. 增加非法状态、空回答、陈旧版本、白名单、跨运行、新进程恢复和离线回退测试。

终审API探针确认：

```text
waiting_for_input
→ pause
→ paused_from_status=waiting_for_input
→ resume(answers=[])
→ HTTP 409
```

显式`confirm_no_additional=true`可进入`waiting_human_review`，重复暂停返回409。
