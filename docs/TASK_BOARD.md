# 项目任务台账

**版本**：v0.4
**日期**：2026-08-09
**维护者**：若翎的项目统领Codex对话
**用途**：在不固定成员岗位的前提下，协调多人、多Codex对话和多种交付方式。

## 使用规则

1. 一个任务只对应一个明确成果；目标明显不同就新开任务和新对话。
2. 每个任务在开始前登记负责人、协作者、复核人、输入、输出和验收条件。
3. 同一成员可以负责多类任务；同一任务也可以多人协作。
4. 普通分析任务优先写入独立 `handoffs/` 目录，避免直接改核心文档。
5. 吴、钟、刘、夏只在独立 `handoffs/` 任务目录工作，不向远端提交；若翎自己的并行开发任务可按需要使用Git worktree/分支。
6. 成员完成任务后发送“我要同步”，由Codex按 [`SYNC_WORKFLOW.md`](SYNC_WORKFLOW.md) 生成交付包；若翎审查后再决定是否合并。
7. 任务完成后，由若翎或项目统领对话把状态改为“已完成”，并把需要长期保留的结论合并到核心文档。

## 状态定义

- **待认领**：目标已明确，尚无负责人。
- **进行中**：已有负责人和独立对话。
- **待复核**：交付包已完成，等待指定复核人或若翎检查。
- **已完成**：成果已验收并完成必要的项目文档更新。
- **阻塞**：缺少必要输入，且当前无法继续；必须写明阻塞条件。

## 新任务模板

复制下列行并填写，不确定的信息写“待确认”：

```markdown
| `类型-编号` | 单一成果目标 | 负责人 | 协作者 | 复核人 | `[任务编号] 成果名称 - 成员姓氏` | 项目版本/日期 | `handoffs/成员/任务编号-任务名/` | 待认领/进行中 | 下一步动作 |
```

## 任务完成口令

成员确认任务成果已经完成后，在原任务对话中发送：

```text
我要同步
```

此口令只表示“整理并打包当前任务成果”，不表示提交Git、推送GitHub或直接改动若翎的主项目。Codex的具体动作见 [`SYNC_WORKFLOW.md`](SYNC_WORKFLOW.md)。
