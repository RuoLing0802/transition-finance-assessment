# 项目简要待办清单

**版本**：v1.2
**日期**：2026-08-15
**维护者**：若翎的项目统领Codex对话
**用途**：可选地记录重要待办和下一步；不是任务启动、成员交付或项目决策的前置条件。

## 使用规则

1. 只记录需要跨对话追踪、容易遗忘或有明确时点的重要事项；短任务可以不登记。
2. 可填写事项、建议负责人、状态、下一步和备注，不要求任务编号、任务卡、固定输出目录或独立对话。
3. 同一成员可以承担多类工作，同一事项也可以多人协作；人员不固定绑定岗位。
4. 成员成果可直接发送给若翎；[`handoffs/`](../handoffs/)和固定交接文件仅作可选存档。
5. 事项完成后，由 `01_项目总控与决策` 把需要长期保留的结论更新到正式治理文档。未写入本清单不影响任务有效性。

## 状态定义

- **待安排**：事项已识别，尚未确定启动时间或负责人。
- **进行中**：已经开始处理。
- **待确认**：已有成果或建议，等待若翎确认。
- **已完成**：成果已验收并完成必要的项目文档更新。
- **等待条件**：需要数据、口令、材料或阶段条件后才能开始。

## 可选事项模板

需要记录重要待办时，可复制下列行；不确定的信息写“待确认”：

```markdown
| 事项 | 建议负责人/对话 | 待安排/进行中/待确认/已完成/等待条件 | 下一步动作 | 备注 |
```

## 可选任务说明

如任务较复杂，若翎可以另行说明目标、输入材料、期望成果、来源要求、验收方式和截止时间。是否分配编号、建立单独对话、使用 `handoffs/`、编写 `HANDOFF.md` 或打包ZIP，由实际需要决定，不影响任务开始或完成。
