## 3. 正式数据与模拟数据的边界

### 正式数据

只有命题方或组委会正式提供的数据，才可称为“正式参赛数据”。收到后必须记录文件清单、版本、哈希、来源和用途。根据若翎已确认的项目共享决定，正式数据可进入本项目私有GitHub、五人团队和项目所需的外部模型服务，不把隐私、保密或授权作为工程阻塞项。

### 模拟数据

当前不使用模拟数据。若后续为程序烟雾测试确需构造模拟数据，必须事前取得确认，记录生成规则、随机种子、字段覆盖、局限和用途，并在文件名、表格、图表、日志和报告中显式标注“模拟数据，不代表比赛正式数据”。模拟结果不得用于宣称模型准确率、用户效果、企业评分或金融业务成效。

### 赛题描述

赛题书中的规模、字段、目标值和资源说明属于“赛题描述”，既不等于正式数据，也不等于本项目的实测结果。

## 4. 数据需求

### 4.1 必须向命题方确认

- 正式文件清单、文件格式、版本、哈希和领取方式；
- 数据字典、代码表、单位、空值含义、企业代号规则和行业映射；
- 标签定义、标注指南、金标准、训练/验证/测试划分和时间边界；
- 数据是否包含真实或模拟生成内容，哪些字段可以用于训练、展示和报告；
- 命题方附带的使用说明、字段限制和测试要求，作为数据解释与比赛提交依据记录，但不作为项目内部Git同步和五人协作的阻塞项；
- 异常值、缺失值、重复企业、跨年度口径变化和版本更新机制；
- 统一可运行性测试使用的数据和环境规格。

### 4.2 建议字段

| 数据组 | 建议字段 | 用途 | 关键校验 |
|---|---|---|---|
| 企业主数据 | 企业代号、行业/细分行业、地区、报告期、组织边界 | 主键、行业路由、期间控制 | 唯一性、行业可映射 |
| 能源活动 | 能源类型、数量、单位、月份、设施、凭证号 | 折标与排放核算 | 单位、期间连续、凭证可追溯 |
| 生产经营 | 产品、产量、单位、收入、产能利用率 | 强度指标与行业基准 | 与能耗期间一致 |
| 排放源 | 范围、气体、活动数据、因子ID、边界 | 碳排放核算 | 公式、因子和边界完整 |
| 设备工艺 | 设备类型、型号、投运年限、能效、工艺路线、监测状态 | 路径识别与风险 | 型号、状态和期间可核 |
| 转型目标 | 基准年、目标年、绝对/强度目标、中期节点 | 目标可信度 | 基准口径一致、节点可验证 |
| 转型项目 | 措施、技术、CAPEX/OPEX、预计减排、时间表、责任人 | 行动与资本开支 | 资金、减排、工期闭环 |
| 金融需求 | 金额、期限、用途、还款来源、KPI | 金融业务匹配 | 用途与措施一一对应 |
| 治理保障 | 董事会监督、披露、第三方核验、公正转型措施 | 治理和ESG风险 | 文件证据、责任主体 |
| 证据质量 | 文件哈希、位置、抽取置信度、复核人、时间 | 审计和可解释性 | 每个关键结论可定位 |
| 智能问答标签 | 问题、回答、关键信息、场景标签、推荐路径 | 动态提问评估 | 标注规则、泄漏和划分 |

## 5. 正式数据到达后的审计流程

1. **文件盘点**：登记文件名、格式、大小、哈希、版本、来源和用途。
2. **字段确认**：逐字段对照数据字典，确认类型、单位、取值、空值、主键和时间范围。
3. **结构质量**：检查唯一性、重复、缺失、异常、跨表关联、年度连续性和行业代码。
4. **口径核验**：核对能源单位、折标系数、排放因子、核算边界、生产期间和企业组织边界。
5. **标签与划分**：检查标签定义、标注一致性、训练/测试隔离、时间泄漏、企业泄漏和未来信息泄漏。
6. **处理留痕**：记录数据进入过的脚本、模型、服务、版本和输出位置，便于复现与排错。
7. **可用性分级**：把字段分为可直接使用、人工复核后使用、仅展示、缺失待补和禁止使用。
8. **基准与模型校准**：重新审计权重、阈值、行业基准、补全策略、场景模型和第二深验行业。
9. **金标准与测试集**：与命题方或人工专家确认金标准，锁定测试集，形成版本化测试报告。
10. **文档更新**：同步更新本文件、项目状态、决策、数据契约、规则手册、测试计划和共享说明。

不允许对授信关键字段静默插补。机器补全只能作为候选值，必须保存方法、版本、置信度、原值和人工确认状态。

- 项目任务可按需要把数据发送给外部大模型或其他服务，不需要再次取得隐私、脱敏或保密确认；应记录服务商、模型、用途和输出位置。
- 成员通过GitHub只获取若翎发布的正式版本；成员成果统一通过包含 `HANDOFF.md`、`SYNC_PROMPT.md` 和ZIP的文件交付包发送给若翎，不向正式仓库推送。交付说明必须标明依据的项目版本和日期。
- 临时缓存和无复现价值的运行日志可以继续排除；其他数据、输出和配置由任务需要决定是否进入版本管理。
