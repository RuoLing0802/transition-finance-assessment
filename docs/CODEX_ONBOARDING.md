# Codex接入说明

以下提示词供其他团队成员在克隆、复制或解压本项目后，发送给其自己的Codex。提示词使用项目相对路径，不依赖本机绝对路径。

## 统一接入提示词

```text

请先确认当前使用者是若翎、吴、钟、刘或夏，并确认本次要完成的具体任务。成员姓氏只用于标识交付来源，不对应固定岗位；任何成员都可以参与政策、规则、数据、软件辅助、测试、报告或演示任务。

在读取项目内容前，先按 AGENTS.md 的同步规则检查当前版本：若存在Git远端，由Codex只读检查远端更新，并在本地工作区干净且可以安全快进时同步；若没有Git远端，则比较 docs/PROJECT_STATUS.md 的版本和日期，并询问使用者是否收到若翎更新后的项目包。无法取得新版时，明确报告当前依据的版本和日期。除若翎外，任何成员和Codex都不得向远端推送、创建远端分支或发起拉取请求。
```

## 接入后的期望行为

Codex应把 `docs/PROJECT_CONTEXT.md` 作为主上下文，把 `docs/DECISIONS.md` 作为决策来源，把 `docs/DATA_STATUS.md` 作为数据边界来源，把 `docs/PROJECT_STATUS.md` 作为阶段来源，把 `docs/TASK_BOARD.md` 作为当前任务来源。任何实际任务结束后，应报告新增/修改文件、验证方式、未验证风险和待确认事项；核心文档更新建议写入 `HANDOFF.md`，由若翎的项目统领对话统一合并。

成员不需要掌握Git命令，也不向GitHub提交成果。Codex只负责检查和获取若翎发布的最新版本；本次成果全部整理到 `handoffs/<成员姓氏>/<任务编号-任务名>/`。

任务完成后，成员只需发送完全一致的口令“我要同步”。Codex必须读取 `docs/SYNC_WORKFLOW.md`，检查本任务文件，生成或更新 `HANDOFF.md` 和 `SYNC_PROMPT.md`，压缩任务目录，并把ZIP路径、文件清单和发送给若翎的方法告诉成员。不得在该流程中执行Git提交或推送。
