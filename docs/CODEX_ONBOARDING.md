## 接入后的期望行为

Codex应把 `docs/PROJECT_PLAN.md` 作为唯一正式总体计划，把 `docs/PROJECT_CONTEXT.md` 作为主上下文，把 `docs/DECISIONS.md` 作为决策来源，把 `docs/DATA_STATUS.md` 作为数据边界来源，把 `docs/PROJECT_STATUS.md` 作为阶段来源。`docs/TASK_BOARD.md`仅是可选待办，不是任务启动前置条件。

任何实际任务结束后，应报告完成内容、文件或材料、来源和验证方式、未验证风险、待确认事项以及对正式项目的建议影响。“依据的项目版本”优先填写开始工作时的Git提交短哈希，并可附计划/状态版本和日期。成员可把消息、文档、代码片段、数据结果或ZIP直接发送给若翎，不需要固定目录或交接文件；本地成果可放在仓库外或仓库内自选清楚路径，仓库内成果不得覆盖核心治理文档或正式代码，也不得提交或推送。

若翎在 `01_项目总控与决策` 中先把成员成果分为新增、重复、冲突、过时和待确认内容，给出“建议采纳、部分采纳、暂不采纳”的审查结论；若翎确认后再更新正式文件、验证、提交和推送。具体流程见 [`SYNC_WORKFLOW.md`](SYNC_WORKFLOW.md)。
