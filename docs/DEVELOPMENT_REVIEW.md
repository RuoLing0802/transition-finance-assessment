## 4. 配套数据的产品定位调整

当前配套工作簿是命题方提供的脱敏、模拟生成的比赛开发测试数据，不是真实企业业务数据，也不是正式训练数据、正式评分标签或真实融资依据。

本项目后续应把它作为当前唯一的基准业务场景，而不是普通的可选上传样例：

1. 系统打开后默认进入配套数据集；
2. 用户直接从企业列表中选择企业；
3. 上传 PDF、DOCX、图片或其他文件时，将其视为当前企业的补充证据；
4. 参考结论只在“验证对照”中出现；
5. 数据来源、模拟数据声明、批次哈希和规则版本放入信息检查器，不占用中央对话空间；
6. 如果评测方之后提供其他文件，应作为新的受控数据批次或当前企业补充证据接入，不能改变配套数据的基准定位。

应用体验可以支持在同一工作空间连续评估多家企业，但内部仍应保持“一次评估运行绑定一家企业”。这样可以支持企业切换和比较，同时避免将不同企业的事实混入同一会话上下文。

### 6.1 当前实际技术架构

- **当前前端**：React、TypeScript、Vite、Ant Design和ECharts专业Agent工作台，由FastAPI提供构建产物和API。
- **编排运行时**：LangGraph负责运行级节点、条件路由和检查点；LangChain Core只包装确定性节点；SQLite是持久化状态真实来源。
- **当前后端**：Python、FastAPI、Pydantic、SQLite，配合 `openpyxl` 和已有 M1 核心规则。
- **模型接入**：OpenAI 兼容接口、用户自定义模型配置、能力目录、离线回退；模型用于会话调度，不是评分引擎。
- **凭据限制**：当前自定义模型API Key保存在本机应用数据目录的SQLite中，接口列表和前端不会回传密钥，但数据库内仍是本地明文存储。该方案只作为本地MVP基线接受；正式分发前应迁移到macOS Keychain、Windows Credential Manager或等价系统凭据存储，并补充文件权限、迁移和删除测试。
- **多模态**：PyMuPDF、`pdfplumber`、`python-docx`、`openpyxl`、PaddleOCR 和外部视觉模型适配。
- **桌面封装**：PyWebView、PyInstaller；macOS 已有本地构建成果，Windows 暂缓。
- **规则与核算**：应继续采用独立、可回放、可版本化的 Python 规则/计算模块，不让模型直接决定事实和评分。

## 7. UI 审查结论

M2审查时的静态网页虽然具备左侧任务栏、中央对话区和右侧企业信息栏，但呈现方式偏向“功能验收后台”。该问题已经在M3通过React专业Agent工作台重构，以下原则保留为后续UI优化基线。

### 左侧任务栏

- 工作空间；
- 企业评估运行列表；
- 当前企业；
- 新建评估；
- 最近运行；
- 侧栏边缘收起按钮。

配套数据只显示一行简要状态，哈希、批次和规则版本移到右侧检查器。

### 中央对话区

只保留当前企业、评估阶段、简洁消息、关键结果卡片、输入框、附件按钮和模型选择器。

默认隐藏：

- 原始批次 ID 和 SHA-256；
- 全部工具调用步骤；
- 大量指标卡；
- 参考结论表格；
- 详细审计事件；
- 报告生成面板。

### 右侧信息检查器

按可折叠区提供：企业画像、质量信号、能耗变化、碳排放测算、行业对标、转型路径、证据材料、参考答案对照和运行来源。

## 8. RAGFlow 判断

当前不建议把 RAGFlow 加入本地软件或当前 MVP。RAGFlow 官方定位是基于深度文档理解的开源 RAG 引擎，适合复杂文档解析、知识库检索和带引用的问答；它不是碳排放计算器、评分引擎或授信决策引擎。详见 [RAGFlow 官方 Quickstart](https://github.com/infiniflow/ragflow/blob/main/docs/quickstart.mdx)。

官方部署路径需要 Docker 和多项服务，文档列出了 x86 CPU、内存、磁盘以及 Elasticsearch/Infinity、MySQL、MinIO、Redis 等运行依赖；ARM64 镜像也不是官方默认分发路径。详见 [RAGFlow 官方 README](https://github.com/infiniflow/ragflow) 和 [Docker 配置说明](https://github.com/infiniflow/ragflow/blob/main/docker/README.md)。这与当前轻量本地网页、macOS 单机应用和离线回退目标不匹配。

当前更合理的做法是先预留：

```text
knowledge_source
knowledge_document
evidence_ref
rule_catalog
factor_registry
rule_version
factor_version
effective_date
jurisdiction
```

未来若政策、行业标准、排放因子和外部碳资料明显增多，再将 RAGFlow 作为独立后端服务接入：

```text
RAGFlow 检索证据
→ 人工/规则复核
→ 版本化规则或因子库
→ 确定性计算
→ 行业对标与评分
```

RAGFlow 的检索结果不得未经复核直接成为评分输入或信贷结论。
