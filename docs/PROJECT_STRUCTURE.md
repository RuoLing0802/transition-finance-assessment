# 项目目录与十模块导航

**版本**：v1.2
**日期**：2026-08-22
**用途**：说明物理目录、十个产品模块和文件权威层级；不改变现有程序包、接口或MVP范围

## 1. 整理原则

- 代码、API、测试、配置和运行时依赖路径继续使用英文，避免跨平台、打包和导入问题。
- 赛题材料、团队成果和历史资料使用中文目录，便于人工查找。
- 十个产品模块用于逻辑导航，不强行把现有代码拆成十个物理包，也不创建没有内容的空目录。
- 成员交付先进入`团队成果/`，只有经过01审查并写入`docs/`后才成为正式项目结论。
- 软件硬编码依赖的配套数据目录和ZIP保留在根目录并继续被`.gitignore`排除，不上传公开GitHub。

## 4. 文件权威层级

1. `AGENTS.md`：当前任务规则、安全和权限边界。
2. `docs/PROJECT_PLAN.md`：唯一正式总体计划。
3. `docs/PROJECT_CONTEXT.md`、`PROJECT_STATUS.md`、`DECISIONS.md`、`DATA_STATUS.md`：正式上下文、状态、决策和数据边界。
4. 专项正式文档：数据画像、数据契约、开发简报、开发审查、政策规则审查等。
5. `团队成果/`：成员原始交付；可追溯但不自动成为正式结论。
6. `项目材料/历史规划/`和`handoffs/`：历史追溯资料；不重新作为当前指令执行。

发生冲突时按上述顺序处理，并在`docs/DECISIONS.md`登记需要长期保留的调整。

## 5. 命名和新增文件规则

- Python包、TypeScript模块、数据库迁移、API契约、测试和构建文件继续使用ASCII英文命名。
- 研究材料和成员成果可使用中文目录；文件名保留来源、版本和主题。
- 当前有效的长提示词统一放入`项目材料/执行提示词/`，失效或完成后移入`项目材料/历史规划/`并记录替代关系。
- 政策/标准原件后续建议放入受控知识原件目录并使用稳定ID，不在代码中硬编码中文个人路径。
- 不在根目录直接堆放新的成员交付；按成员和最接近的十模块归档。
- 不因十模块导航移动已运行代码或重写导入路径；需要重构时另行交02并完成回归测试。
