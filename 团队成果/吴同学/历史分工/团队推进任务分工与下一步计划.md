# 团队推进任务分工与下一步计划

## 一、当前数据口径

`配套数据.xlsx` 已确认是命题方提供的正式配套数据。

根据赛题文件，数据中的企业、能耗、经营、设备、痛点和转型建议均为脱敏或模拟生成数据，仅用于比赛开发、训练、测试和演示，不代表真实企业业务数据，不得用于真实企业转型融资认定、碳排放核算或授信决策。

赛题所述 500+ 条问答语料和 30 组模拟对话没有独立明细文件，其结果统一体现为 Excel 中的 AI 建议测试标签数据。

数据角色应明确区分：

| 数据角色 | 对应内容 |
|---|---|
| 基础输入 | 企业、行业、地区、规模、成立年份 |
| 计算输入 | 能源消费、用水、产量、营业收入 |
| 管理输入 | 设备、设备年限、在线系统、余热回收、光伏、绿电比例 |
| 可选交互输入 | 当前主要痛点、企业自述转型诉求 |
| AI 测试标签 | 建议改进方向、匹配转型路径、近中长期行动建议 |
| 知识候选库 | 转型目录 |
| 待外部补充 | 折标系数、排放因子、行业基准、政策标准原文 |

## 二、未来 7—10 天推进计划

### 第一阶段：正式数据审计（1—2 天）

目标是确认数据能否直接进入系统。

具体工作：

1. 建立完整数据字典；
2. 登记文件来源、版本、哈希和使用边界；
3. 检查 1000 户企业的主键、字段类型、单位、缺失和异常；
4. 建立行业—细分行业—产品—产量单位映射；
5. 分析缺少产品产量的企业；
6. 检查能源来源与实际能源字段是否一致；
7. 输出字段可用性分级：
   - A：可直接使用；
   - B：规则校验后使用；
   - C：动态提问或人工补充后使用；
   - D：仅作标签或展示；
   - E：禁止作为模型输入。

交付物：数据字典、数据质量审计表、字段可用性分级表、数据问题与处理建议清单。

### 第二阶段：AI 标签专项审计（2—3 天）

需要明确以下任务的输入和标签：

1. 痛点识别；
2. 转型目录多标签推荐；
3. 近、中、长期行动建议生成；
4. 动态提问触发；
5. 回答结构化抽取；
6. 企业场景识别。

重点检查：

- 标签在各行业的分布；
- 每条企业记录包含多少推荐路径；
- 推荐路径能否在转型目录中找到；
- 路径名称、编号和层级是否统一；
- 标签是否高度模板化；
- 是否存在输入字段直接包含标准答案；
- 同一模板是否同时进入训练集和测试集；
- 痛点和诉求应作为输入、标签，还是分别开展实验。

建议设计两套实验：

- 基础模式：使用基本信息、能耗和设备管理字段；
- 交互增强模式：加入痛点、诉求及动态提问获得的信息。

两者比较，才能评估动态提问是否真正提高推荐质量。

交付物：AI 任务定义表、输入—标签隔离表、标签泄漏检查表、标签分布和模板重复分析、训练验证测试划分建议。

### 第三阶段：政策、标准与核算规则（3—5 天）

优先处理：

1. 各能源折标准煤系数；
2. 电力、煤炭、天然气、柴油、汽油和热力排放因子；
3. 适用年份、地区和核算边界；
4. 11 个行业的政策与标准目录；
5. 8 行业系统配置框架；
6. 铜产业第一深验规则；
7. 第二深验行业选择。

第二深验行业应综合比较：数据完整度、产量字段覆盖率、转型目录丰富度、权威标准可得性、与铜产业的差异性、演示效果和金融业务价值。

交付物：政策与标准来源台账、折标和排放因子表、行业映射表、铜产业规则说明、第二深验行业比较表。

### 第四阶段：评分与动态提问设计（3—5 天）

评分输出应分为三部分：

1. 数据可信度等级；
2. 转型评估得分；
3. 风险红旗。

动态提问优先解决会改变计算或推荐结果的信息缺口，例如：

- 产量缺失；
- 核算边界不明；
- 能耗变化但经营规模变化不明；
- 设备型号和能效等级缺失；
- 转型项目 CAPEX、时间表或责任人缺失；
- 推荐路径所需条件未确认。

每个问题需要记录触发条件、问题文本、期望回答字段、回答校验规则、对核算和推荐的影响、人工复核要求及停止条件。

交付物：指标和评分规则表、风险红旗清单、动态提问决策树、提问停止规则、人工复核规则。

### 第五阶段：测试与验收体系（2—3 天）

建议建立：

- 数据质量测试集；
- 能源折标人工金标准；
- 碳排放人工金标准；
- 行业路径推荐测试集；
- 动态提问测试场景；
- 文本建议人工评分表；
- 性能测试口径。

由于命题方没有提供逐轮对话明细，动态提问专项测试需要项目自行构造，并标记为“项目根据命题方标签和字段缺口构造的测试场景”，不得冒充命题方原始 30 组对话数据。

## 三、五人团队分工

### 若翎：项目总控与技术集成

- 确认数据使用口径；
- 确定输入字段、标签和知识库边界；
- 决定第二深验行业；
- 审定评分体系和技术接口；
- 整合成员成果；
- 决定何时启动 MVP；
- 后续负责正式开发和 Git 操作。

当前主要输出：统一数据任务说明、验收标准、决策清单、开发前规格冻结。

### 吴：数据字典与质量审计

- 编制五张工作表的数据字典；
- 检查缺失、重复、异常和单位；
- 核验企业代号跨表一致性；
- 开展产量缺失专项分析；
- 建立行业、细分行业和产品映射；
- 完成字段可用性分级。

验收标准：每个字段都有含义、类型、单位、空值解释和用途；所有质量问题都有数量、企业范围和处理建议；不修改命题方原始文件。

### 钟：政策标准与行业规则

- 核验权威政策和标准原文；
- 整理折标系数与排放因子；
- 梳理 11 个行业标准覆盖；
- 完成铜产业深验；
- 核验转型目录引用；
- 提出第二深验行业比较结果。

验收标准：每项规则有标题、机构、版本、日期、适用范围和链接；明确区分已核验、待核验和专业判断。

### 刘：AI 标签与动态提问

- 分析 AI 建议标签分布；
- 清洗并层级化路径标签；
- 建立输入—标签隔离；
- 检查标签泄漏；
- 设计动态提问触发规则；
- 设计基础模式与交互增强模式。

验收标准：每个 AI 任务有明确输入、输出和评价方法；测试标签不进入输入；能够解释标签模板化程度；明确不能由现有数据验证的赛题指标。

### 夏：评分、测试与展示验收

- 设计数据可信度评分；
- 提出转型评分候选规则；
- 建立风险红旗；
- 制作人工金标准样例；
- 设计动态提问测试场景；
- 制定推荐相关性人工评分表；
- 提出演示案例选择标准。

验收标准：每项测试可重复；明确预期输入和预期结果；严格区分赛题目标指标与项目实测结果；演示案例覆盖完整、缺失和冲突等场景。

## 四、团队协作方式

每位成员交付时统一说明：

- 依据的 Git 版本和日期；
- 使用的文件；
- 完成内容；
- 数据或政策来源；
- 已验证内容；
- 未验证内容；
- 发现的风险；
- 需要若翎决定的问题。

不要求成员提交 Git，也不要求固定任务编号。成果可直接发送给若翎，由项目总控进行“新增、重复、冲突、过时、待确认”分类，提出采纳建议，待确认后写入正式项目。

## 五、开发启动条件

不需要等所有政策研究全部结束，但至少应先完成：

- 数据字典初版；
- 字段可用性分级；
- 输入—标签隔离；
- 行业映射；
- 基础折标与排放因子方案；
- MVP 验收测试清单。

完成后，如决定进入开发阶段，需要发送完全一致的口令：

> 开始开发MVP

当前项目仍处于正式配套数据审计与开发准备阶段，软件开发尚未授权。
