## 四、P0阻断项

以下问题必须全部修复，任何一项未完成都不得再次提交01终审。

### P0-1 修复跨行业、跨运行切片读取

当前问题：

- 普通检索列表会按当前企业行业过滤；
- 但`get_chunk(assessment_run_id, chunk_id)`只验证切片属于冻结索引；
- 已实测铜企业`TF0001`可通过已知`chunk_id`读取钢铁专属来源`STD-007`。

整改要求：

1. 切片详情读取必须重新取得服务端绑定的：
   - `workspace_id`
   - `assessment_run_id`
   - `enterprise_id`
   - `thread_id`
   - 当前企业行业
   - 冻结的`index_version_id`
2. 切片必须同时满足：
   - 属于当前运行冻结索引；
   - `industry_scope`包含当前规范化行业，或经过治理明确标记为`global`；
   - 可见性为当前运行允许读取的等级；
   - 不属于其他企业或其他运行的私有证据。
3. 推荐进一步要求：普通用户展开的切片应已经由当前运行的某次检索返回并记录在检索日志中；如不采用该限制，必须说明等价的防枚举和运行归属方案。
4. 跨行业、跨运行、跨企业、跨thread读取应返回404或409，不得返回切片正文，也不得泄露该切片是否存在于其他行业。

必须新增真实测试：

- 铜运行读取钢铁专属切片：拒绝；
- 钢铁运行读取同一钢铁切片：允许；
- 运行A读取运行B的检索日志或私有结果：拒绝；
- 企业A与企业B共享全局政策时，仍分别记录自身运行ID和知识版本；
- 构造或替换前端参数不能绕过服务端行业绑定。

### P0-2 普通检索不得自动构建或重建索引

当前问题：

```python
def ensure_index(...):
    return status if available else rebuild()
```

这使普通检索在索引不存在时直接触发全局知识导入，绕过管理员确认。

整改要求：

1. 普通检索API和Agent工具只能读取已经成功构建的索引。
2. 索引不存在、构建失败或版本不可用时，返回明确、可处理的状态，例如：
   - `knowledge_index_not_ready`
   - `knowledge_index_build_failed`
   - `pinned_index_unavailable`
3. `dry-run`和`rebuild`继续只允许受控管理员/诊断入口调用。
4. 前端显示“索引尚未准备，请由管理员构建”，不得在普通检索请求中隐式构建。
5. 如采用受信任的本地启动预构建机制，必须与普通用户请求分离，记录构建事件并保持可关闭；不得把普通搜索当作管理员确认。

必须新增测试：

- 空数据库普通检索不会生成索引；
- 无管理员凭证不能调用重建接口；
- 管理员构建后普通检索可以正常使用；
- 构建失败不会留下伪“可用”索引。

## 五、P1检索与治理契约整改

### P1-1 严格区分`metadata_only`和正文检索

1. `metadata_only`只能参加：
   - `tier=0`：来源ID、标准号或文号精确匹配；
   - `tier=1`：规范化完整标题匹配。
2. `metadata_only`不得参加普通FTS相关性召回和关键词降级召回。
3. 元数据结果的`excerpt`、`locator`和`chunk_id`必须为空。
4. 明确显示“正文不可用/待OCR/待定位，不得引用条款”。
5. 增加测试：用标题中的普通关键词查询时，不得把`metadata_only`当普通正文结果返回。

### P1-2 修复FTS5字段权重和稳定排序

当前FTS表前3列是`UNINDEXED`字段，现有`bm25(...)`参数没有对应到预定的标准号、标题、章节和正文列。

必须实现并测试：

1. 标准号：12；
2. 标题：10；
3. 章节/表题：6；
4. 正文：1；
5. 未索引列权重显式设为0；
6. 同tier内依次按：
   - 来源角色；
   - `chunk`优先于`source_metadata`；
   - BM25分数；
   - 核验状态；
   - 来源ID；
   - 切片ID或文档ID；
7. 相同索引、知识时点、查询和过滤条件多次运行必须返回相同顺序。

### P1-3 真正应用`knowledge_as_of`

当前虽然冻结了`knowledge_as_of`，但检索候选过滤没有使用它。

整改要求：

1. 检索前应用：

   ```text
   effective_at <= knowledge_as_of
   且 expires_at 为空或晚于 knowledge_as_of
   ```

2. 尚未生效、已经失效或适用日期不确定的来源必须明确降级或排除。
3. 只有年份的来源标记`date_uncertain=true`，不能静默按1月1日处理。
4. 运行冻结后不得因系统日期变化而改变结果。
5. 新增未生效、已失效、只有年份、历史运行回放测试。

### P1-4 行业范围不得默认全局

当前未命中硬编码映射的来源会默认`["global"]`，可能把未治理来源推广到全部行业。

整改要求：

1. `global`必须来自明确的治理字段或白名单决策；
2. 未确认行业范围的来源不得默认全局，可降为`metadata_only`、`blocked`或行业待确认；
3. 研究文献是否全局适用也必须由用途治理明确，不得因为它是文献就自动全行业；
4. 11行业专属来源使用可审计的数据映射，不要把新的来源ID不断散落硬编码在业务逻辑中；
5. 未知行业、空行业和别名无法规范化时不得套用最近行业。

### P1-5 验证本地原件真实SHA-256

整改要求：

1. 构建manifest前读取文件字节并重新计算SHA-256；
2. 实际哈希必须与20号台账、条款表或文献表记录一致；
3. 哈希缺失或不一致时：
   - 正文禁止进入`searchable_candidate`；
   - 记录实际哈希、台账哈希和阻断原因；
   - 不得静默继续切片；
4. 相对路径失效时，不得只凭唯一文件名在整个项目目录匹配原件；
5. 如果提供回退查找，只能基于经过确认的SHA-256，并记录`mapping_method`；
6. 同名不同哈希不得合并；相同哈希的副本才可去重；
7. 文献哈希缺失时不得使用`literature_id`的哈希冒充文件哈希。

### P1-6 索引和准入历史不可原地覆盖

1. 相同manifest重复构建应直接复用现有索引，不删除并重写成员和FTS记录；
2. 准入状态、来源版本、文件哈希、行业范围、排序、token或知识时点策略变化时，生成新索引版本；
3. 历史索引成员、准入决策和旧日志引用必须可回放；
4. 准入决策只能追加替代关系，不得原地改写历史；
5. 当前运行继续使用冻结版本，不得静默升级。

### P1-7 URL和知识内容安全

1. 前端可点击链接只接受合法的`http://`或`https://`URL；
2. 非法协议、脚本协议、本机文件路径和空白伪URL不得返回前端；
3. PDF、网页、工作簿和检索切片中的指令性文字一律作为不可信数据；
4. 检索正文不得改变系统提示、白名单、管理员权限、企业绑定或工具边界；
5. 增加恶意URL和提示注入测试。

## 六、Agent与离线流程整改

### 6.1 修复离线`search_knowledge`

当前离线流程识别到“知识/依据/来源/标准”后，对`search_knowledge`传入空参数，工具实际失败，但界面仍显示“已读取”。

整改要求：

1. 离线检索使用用户当前问题作为`query`；
2. 只有工具真实返回成功结果时才显示“已检索知识依据”；
3. 工具失败、索引未准备或无结果时如实显示原因；
4. 离线模板至少输出：
   - 找到几条候选证据；
   - 来源ID、标题、版本和定位；
   - 当前行业与知识版本；
   - 使用边界；
   - 或“证据不足，需要补充材料/人工复核”；
5. FTS5不可用时应使用确定性降级，并明确标记降级模式。

### 6.2 完成外部模型的受控工具结果解释闭环

当前外部模型先生成回答，再执行工具；工具结果没有进入受控解释步骤，中央回答不能真正依据检索结果形成编号引用。

整改要求：

1. 采用清晰的两阶段或等价流程：

   ```text
   模型提出受控工具调用
   → 后端执行只读工具
   → 将经过裁剪、标记为不可信数据的工具结果交给解释阶段
   → 生成简洁结论和编号引用
   ```

2. 第二阶段不得再次决定准入、改变行业范围、修改事实或执行规则；
3. 模型只能引用工具真实返回的`source_id/chunk_id`；
4. 无结果时不得补写政策、条款或因子；
5. 不展示模型私有思维链；
6. `search_knowledge`加入普通用户可见的安全处理摘要标签；
7. 增加模型伪造引用、引用未返回切片和工具结果提示注入测试。

## 七、前端整改

### 7.1 修复运行切换竞态

当前运行A检索未完成时切换到运行B，A的异步响应可能覆盖B的知识面板。

4. 旧请求晚到不得恢复旧运行证据；
5. 新增前端单元测试模拟慢请求和运行切换。

### 7.2 显示运行冻结版本而不是全局当前版本

   - `allowlist_version`
   - 当前行业过滤

### 7.3 补齐知识面板验收细节

1. 增加来源角色筛选；
2. 显示全部重要警告，不只显示第一条；
3. 明确区分候选正文、仅元数据、待OCR、研究文献和证据不足；
4. 证据详情使用右侧抽屉或不挤占中央对话的等价交互；
5. 不返回或展示本机绝对路径；
6. 非法URL不渲染为链接；
7. 为`KnowledgePanel`、证据卡、空结果、降级、版本显示和运行切换增加组件测试。
