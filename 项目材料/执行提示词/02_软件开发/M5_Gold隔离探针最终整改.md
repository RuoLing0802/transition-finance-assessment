## 一、复审结论

01已经确认以下四项主整改有效：

- Gold未命中目标的11条不再误判为通过；
- 12篇中文文献、16条研究片段已按治理边界显式设为`global`研究证据，11行业可检索；

- FTS5已经使用8列BM25权重。

当前唯一剩余阻断是`KnowledgeService._run_isolation_gold_probe()`依赖数据库中的前两个评估运行：

```python
run_a, run_b = run_ids[:2]
```

如果这两个运行都合法返回同一条`global`研究证据，`run_b`读取该切片本来就是允许的，探针却把“未拒绝”误判为隔离失败。独立11行业工作空间复验得到：

```text
31 passed / 11 correct_degrade / 2 failed
```

两条失败均为`N-S2-05`、`N-S2-06`。固定TF0001/TF0002测试夹具得到`33 passed / 11 correct_degrade / 0 failed`，说明当前Gold结论受运行顺序影响，不能作为正式可重复验收结果。

## 二、整改要求

1. 不得再使用任意“前两个运行”作为隔离测试对象。
2. 为跨运行、跨企业、跨线程隔离分别建立受控测试上下文，测试对象必须满足：
   - 明确属于同一工作空间或明确属于不同工作空间；
   - `assessment_run_id`、`enterprise_id`和派生`thread_id`均已知；
   - 用于越权读取的切片只记录在源运行检索日志中，未记录在目标运行检索日志中；
   - 不得用两个运行都合法返回的`global`切片作为越权对象。
3. 优先从`run_a`已经返回、但`run_b`尚未返回的切片中选择探针对象；找不到合格对象时，应返回明确的`env_blocked`及原因，不得误报`passed`或`failed`。
4. `N-S2-05`与`N-S2-06`必须分别验证其声明的边界，不得只复用一个不能区分企业、运行和线程的布尔结果。
5. Gold执行必须与数据库中工作空间、运行数量和创建顺序无关。
6. 不得削弱当前`get_chunk`后端约束，不得通过给目标运行预先写入同一切片日志来制造通过。

## 三、必须新增的回归测试

至少新增：

1. 同一工作空间11个行业运行，按任意顺序创建，Gold结果稳定为：

   ```text
   33 passed / 11 correct_degrade / 0 failed
   ```

2. 前两个运行均能合法检索同一`global`研究片段时，不应把该片段当作越权探针，也不应误报失败。
3. 一个只在`run_a`检索日志中出现的切片，由`run_b`读取时必须被拒绝。
4. 不同企业、不同`assessment_run_id`、不同`thread_id`分别有明确断言。
5. 改变工作空间和运行创建顺序后，44条Gold的状态分布保持一致。

测试不得只断言总数；需要断言`N-S2-05`、`N-S2-06`各自的探针对象、源运行、目标运行、拒绝原因和边界类型。
